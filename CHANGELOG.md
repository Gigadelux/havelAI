- 2026-11-21: offline unit tests in `src/tests/` and `model/tests/`.
- 2026-11-25: `model/train/runpod_launch.py`: trains on a RunPod GPU pod over SSH, with no network volume (`up`, `push`, `train`, `status`, `logs`, `pull`, `down`, and `run` for all of it, which always terminates the pod). Pod size (RUNPOD_*) and training memory (TRAIN_*) are set in `.env`; `example.env` documents them. Dry run unless `--yes`; hourly-rate limit; training time limit. Tests in `model/tests/test_runpod_launch.py` (offline, fake SDK and ssh).
- 2026-11-25: the launcher creates its own SSH key (`gitignore/temp/runpod_ed25519`) on the first `--yes` when `RUNPOD_SSH_KEY` is empty, so `RUNPOD_API_KEY` is the only value to fill in. A key set in `RUNPOD_SSH_KEY` is never generated.
- 2026-11-25: optional RunPod network volume for download caches only (`RUNPOD_NETWORK_VOLUME_ID`, mounted at `/workspace`; uv, pip and Hugging Face caches in `/workspace/havelai-cache/`), so later pods skip the ~3.5 GB package download. Requires `RUNPOD_DATA_CENTER`. Data, venv and checkpoints stay on the container disk.
- 2026-11-25: `train.py --gradient-checkpointing` to trade compute for activation memory.
- 2026-11-25: `runpod>=2.4.0` (MIT) added in a new `cloud` dependency group. Resolving it with the rest moved `python-dateutil` from 4.0.0 to 2.9.0.post0 in `uv.lock` and `requirements.txt` (runpod's boto3/botocore needs `<3`).
- 2026-11-26: `model/export/hf_publish.py`: exports the trained checkpoint to ONNX (fp32) and ONNX dynamic int8, checks both against the fp32 PyTorch model on the held-out test split, writes the model card and uploads `Gigadelux/havel_base` (private) to Hugging Face. Dry run unless `--yes`. `onnx`, `onnxruntime`, `onnxscript` and `huggingface_hub` added to the `model` extra. Tests in `model/tests/test_hf_publish.py`.
- 2026-11-26: data-write architecture in `src/repositories/`: abstract `Repository`, `VectorRepository` and `RecordRepository` bases (`base.py`), vector connectors for Milvus Lite (local `.db` file) and Qdrant (hosted), and `factory.py` to pick a connector from the config. Shared service core in `src/services/common/` (`Config`/`VectorConfig`/`ModelConfig` with weight validation, `.env` reader, `Layer` protocol, csv/parquet/sqlite text ingest). New optional extras `havelai[local]` and `havelai[hosted]`; the core library stays stdlib-only.
- 2026-11-26: regex layer: about 60 static, hand-written patterns (6–8 per attack class, keyed by `AttackType`) in `src/data/regex_patterns.py`, and `regex_catch` in `src/services/local/regex_catch.py` (the hosted service reuses it). Binary contribution: 1 if any pattern matches, else 0; matched pattern ids are kept for analytics.
- 2026-11-26: model layer. Local `src/services/local/model_catch.py`: downloads `havel_base` (ONNX int8 by default, fp32 optional) from Hugging Face, logs the download, and runs it with onnxruntime + tokenizers (no torch) on sentence-aligned chunks whose size grows with the input (`src/services/common/chunking.py`, `clamp(64, 512, 32·⌈√tokens⌉)`); the prompt score is the highest chunk `p_injection`. Hosted `src/services/hosted/model_catch.py`: guard models over an OpenAI-compatible chat-completions endpoint (OpenRouter by default), with adapters for `openai/gpt-oss-safeguard-20b` (taxonomy policy, JSON output) and Llama Guard (`safe`/`unsafe` + category).
- 2026-11-26: vector layer `vector_learning_catch.py` (local: Milvus Lite file; hosted: Qdrant) with fastembed embeddings (`src/services/common/embedder.py`, default `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, 384 dimensions). Three phases: `initialize` (known attack texts from a csv/parquet/SQLite text column), `learn` (stores chunks whose regex + model score reaches `learn_threshold`, default 0.7) and `detect` (highest cosine similarity and the top 10 similar texts; flagged at `catch_threshold`, default 0.8).
- 2026-11-26: `detector_engine.py` for the local and hosted services and the public API `from havelai.local import Havel` / `from havelai.hosted import Havel`: chainable `Config(...)`, `VectorConfig(...)`, `ModelConfig(...)`; `detect(prompt)` returns a `DetectionReport` (`src/analytics/report.py`) with every layer's score, weight and contribution, thresholds, timings, chunking, versions and the vector top 10; `save(path)` copies the vector store to a Milvus Lite file, `save("hosted")` pushes it to Qdrant. Final score = weighted average (regex 0.1 / model 0.9 while the vector store is empty or off, else regex 0.1 / model 0.65 / vector 0.25).
- 2026-11-26: analytics storage and export. `SCHEMA.sql` (SQLite and PostgreSQL) with `detections`, `layer_scores`, `vector_hits` and `learned_vectors`; record connectors `src/repositories/sqlite.py` (local file) and `src/repositories/remote_http.py` (hosted: POST to an ingest URL with a key from `.env`); `Havel.save_metrics(path | "hosted")`; `Havel.export_metrics_summary(path)` writes a Markdown summary plus matplotlib plots (`src/analytics/export.py`). Prompts are never stored.
- 2026-11-26: `assets/havelai_logo.svg` added as the project logo in `README.md`.
- 2026-11-26: `havel_base` published to Hugging Face as the **private** repo `Gigadelux/havel_base` (revision `2d6d903`): fp32 safetensors, ONNX fp32 and ONNX int8, model card, `havel_meta.json`. Verified with the opt-in real-model test (`HAVEL_RUN_MODEL_TESTS=1`). Stays private until the dataset license is checked.

### Changed
- 2026-11-21: `train.py` now shows tqdm progress bars (per epoch, validation and test; `--no-progress` to turn off) and logs through the `havelai.train` logger to stderr and `<run>/train.log`: start configuration, data warnings, per-epoch progress, and errors with tracebacks. A NaN or infinite training loss now stops the run with a clear error; an interrupted run exits 130 and still exports its partial metrics. `tqdm` is now an explicit `model` dependency.
- 2026-11-21: metrics split out of `train.py` into `model/train/metrics.py`: one class, `TrainingMetrics`, that computes the metrics, records training, and exports JSON tables plus six matplotlib plots into `<run>/metrics/` with `flush()`. New: a validation pass before training and the improvement metrics (change in validation accuracy / macro-F1 / loss per epoch, and the slope of training accuracy over batches). `matplotlib` added to the `model` extra; `uv.lock` and `requirements.txt` regenerated.
- 2026-11-21: one encoder constant, `ENCODER_MODEL` (mmBERT-small), replaces `BASE_MODEL`/`SMALL_MODEL`/`DEFAULT_ENCODER`; `train.py` and the baseline now default to mmBERT-small, since mmBERT-base cannot meet the 256 MB limit.
- 2026-11-21: `model/architecture.py` now defines the two-head model (`HavelForInjectionDetection`, `build_two_head`, `two_head_loss`, `decide`, `class_probabilities`, `type_target_from_record`); the single-head `build_classifier` is unchanged. Tests in `model/tests/test_architecture.py`. Vocabulary pruning, two-head training and the int8 export are not built yet.
- 2026-11-21: `docs/MODEL_ARCHITECTURE.md` now describes the target design (mmBERT-small, 32k vocabulary, int8, binary + attack-type heads) with diagrams, size budget and the list of code still to write; decision logged in `DECISIONS.md`.
- 2026-11-21: root `ARCHITECTURE.md` now covers only the Python library; model material moved to `docs/ENHANCEMENT_PIPELINE.md`, `docs/TRAINING.md` and `docs/MODEL_ARCHITECTURE.md`. `CLAUDE.md` and `README.md` keep short overviews that link there.
- 2026-11-26: model docs moved from `docs/` to `model/docs/` (`TRAINING.md`, `ENHANCEMENT_PIPELINE.md`; `MODEL_ARCHITECTURE.md` merged into the new `model/docs/ARCHITECTURE.md`, which now separates the trained single-head model from the planned two-head design). New `model/docs/METRICS.md` with the measured results of run `mmBERT-small-runpod-20261125T190715Z` and its plots in `model/docs/img/run-20261125/`. `docs/` keeps `TAXONOMY.md`. Links in `CLAUDE.md`, `README.md`, `ARCHITECTURE.md`, `DECISIONS.md` updated.

### Fixed
- 2026-11-21: relative imports in `src/` and `dev-mode-dirs` so the `src` → `havelai` rename works for built wheels and editable installs.
- 2026-11-26: `MilvusLiteRepository.iter_records` reads with plain queries (up to 16,384 rows) instead of `query_iterator`, which Milvus Lite does not fully implement and which logged a gRPC traceback during `Havel.save()`.
- 2026-11-26: count axes in the `export_metrics_summary` plots use whole-number ticks.
- 2026-11-26: `MilvusLiteRepository` loads an existing collection when it reopens a `.db` file; before, search on a reopened store failed with "collection is released".
- 2026-11-26: `hf_publish verify` switches off the padding stored in the checkpoint's `tokenizer.json`. Before, `encode_batch` padded every row to the longest one and the pads were scored as real tokens, so the first verify run (ONNX fp32 binary accuracy 0.727) measured the bug, not the model. The model card snippet also disables padding, and `verify --limit N` now takes a seeded random sample instead of the first N rows (which were all benign). Re-measured: ONNX int8 F1 0.9935, FPR 0.0016, attack-type macro-F1 0.9034 (`model/docs/TRAINING.md`).

### Security
